# RustDM v0.1.0 CLI

Prepared release notes; publication is pending.

The initial CLI supports HTTP/HTTPS downloads with up to 16 transfer workers,
dynamic dispatch of saved ranges, retry, Ctrl+C pause, validated resume, live
speed/ETA, persistent queue/history, aggregate bandwidth limits, and optional
publisher-provided SHA-256 verification before final-file publication.

## Usage

```sh
rustdm download "https://example.com/file.zip" -o file.zip -c 4
rustdm download "https://example.com/file.zip" -o file.zip --resume
rustdm queue add "https://example.com/file.zip" -o queued.zip --limit-rate 1048576
rustdm queue run
rustdm history
```

Use `--sha256 HEX` with a publisher's 64-character expected SHA-256 digest.
Supply it again on direct resume; queued jobs retain it automatically.
`-o` is a destination filename, not only a directory. Existing output files
are never overwritten.

## Compatibility and scope

- Packages cover Windows x86-64 MSVC and Linux x86-64 GNU/glibc.
- Older `.rustidm` partial directories are detected and resumed in place.
- Existing version-1 queue records remain readable; absent rate/checksum options
  mean unlimited bandwidth and no publisher checksum verification.
- New range plans may contain up to 128 parts. Older builds that accepted only
  16 parts cannot resume these larger plans. Saved boundaries remain stable.
- Requests require correct server range/validator behavior for safe resume.
  Servers without it use one stream and cannot resume saved partial data.
- Splitting already active slow ranges, scheduling, FTP, media assembly, desktop
  UI, browser capture, and web management are future work.
- Queue URLs/query parameters are persisted; headers and URL userinfo cannot be
  queued. Direct downloads support request headers supplied in memory.
- Executables are portable CLI packages, without an installer or code signature.

See `docs/RELEASE.md` for package verification and `docs/QUEUE.md` for recovery.
